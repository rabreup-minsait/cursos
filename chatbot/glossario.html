Glossário do curso

Todos os termos técnicos que apareceram ao longo das aulas, explicados de forma direta e com contexto de uso.

ABCD EFGH IJKL MNOP QRST UVWX YZ
A
↑
alucinaçãoaula 09
Comportamento em que o modelo de IA produz uma resposta que parece convincente mas não é verdadeira, pois ele não tem acesso a dados externos e gera texto com base em probabilidades. Uma IA sem contexto real sobre estoque pode dizer que um produto está disponível quando não está. O padrão RAG existe para evitar isso: você fornece os dados reais no prompt antes de pedir a resposta.
APIaulas 03, 07
Interface de Programação de Aplicações. É um contrato que define como dois sistemas se comunicam: quais endereços existem, que dados aceitar e que formato devolver. A API da OpenAI define que você envia um JSON com o modelo e as mensagens para um endereço específico, e recebe a resposta da IA no mesmo formato. O FastAPI permite criar sua própria API para que outros sistemas possam usar o chatbot que você construiu.
appaula 07
O objeto central de uma aplicação FastAPI. Criado com app = FastAPI(), ele registra todas as rotas e é o que o uvicorn usa para iniciar o servidor. O nome app é o que aparece no comando uvicorn main:app: "no arquivo main.py, use o objeto chamado app".
async / awaitaula 07
Palavras-chave do JavaScript que permitem trabalhar com operações que levam tempo, como enviar uma mensagem para um servidor. async marca uma função como assíncrona; await pausa a execução naquele ponto até a operação terminar. Sem o await, o JavaScript tentaria ler a resposta antes de ela chegar. São usados com o fetch() para enviar mensagens ao back-end sem travar a interface.
B
↑
back-endaula 07
A parte do sistema que roda no servidor, invisível para o usuário. É onde ficam a lógica de negócio, a chave da API, o histórico de conversas e todas as regras que não podem ser contornadas. Num chatbot, o back-end é o código Python com FastAPI. O front-end manda mensagens para o back-end, que processa e devolve a resposta.
BaseModelaula 07
Classe do Pydantic usada para definir o formato esperado dos dados que chegam numa requisição. Ao criar uma classe que herda de BaseModel, você declara quais campos a requisição precisa ter e de que tipo. O FastAPI valida os dados automaticamente: se o campo obrigatório não vier ou vier com o tipo errado, devolve um erro 422 antes de entrar na função.
breakaula 01
Comando Python que encerra um laço imediatamente. Num chatbot com while True, o break é o que permite ao usuário encerrar a conversa quando digita "sair". Sem ele, o loop seria infinito e o programa nunca terminaria.
C
↑
chatbotaula 00
Programa que recebe uma entrada do usuário, processa e devolve uma resposta. O fluxo básico é sempre o mesmo: input, processamento e output. O que muda é o que acontece no processamento: pode ser uma simples verificação de palavras-chave, uma consulta a um banco de dados ou uma chamada a um modelo de IA.
classificação de intençãoaula 09
O processo de identificar o que o usuário quer antes de tomar qualquer ação. Uma função que recebe a mensagem e devolve uma categoria, como "dados_usuario", "busca_produto" ou "conversa". Feita por palavras-chave é determinística e barata; feita pela IA é mais flexível mas pode errar. A boa prática é usar palavras-chave para classificar e acionar a IA apenas para gerar a resposta final.
config.pyaula 10
Arquivo Python separado que reúne todos os parâmetros do sistema num único lugar: modelo, temperatura, limite do histórico, nome do bot, system prompt. Com ele, você altera um valor e o efeito se propaga para o sistema inteiro sem precisar varrer cada arquivo. É uma prática de configuração centralizada.
CORSaula 07
Cross-Origin Resource Sharing. Uma proteção do navegador que bloqueia requisições feitas de um endereço para outro diferente. Quando o HTML aberto localmente tenta falar com o servidor Python em 127.0.0.1:8000, o navegador bloqueia por segurança. O CORSMiddleware do FastAPI instrui o servidor a aceitar requisições de outras origens, liberando essa comunicação.
crypto.randomUUID()aula 08
Função nativa do navegador que gera um identificador único no formato xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx. Usada para criar o user_id na primeira vez que o usuário abre o chatbot. O resultado é salvo no localStorage e reutilizado nas visitas seguintes, mantendo a memória da conversa.
D
↑
decoradoraula 07
Uma linha que começa com @ e fica logo acima de uma função para modificar seu comportamento. No FastAPI, @app.get("/") e @app.post("/chat") são decoradores que registram a função como um endpoint: quando uma requisição chega naquele endereço com aquele método, a função logo abaixo é chamada automaticamente.
defaula 00
Palavra-chave Python para definir uma função. Uma função é um bloco de código com um nome que pode ser chamado várias vezes. def normalizar(texto): cria uma função chamada normalizar que recebe um parâmetro texto. Funções bem nomeadas deixam o código mais legível e facilitam a manutenção.
declararaulas 00, 07
Escrever no código a existência de algo: uma variável, uma função, uma classe ou um campo. Declarar uma variável é criar o nome e atribuir um valor: nome = "Ana". Declarar uma função é escrever def normalizar(texto): com seu corpo. No Pydantic, declarar um campo na classe Mensagem é dizer ao FastAPI que a requisição deve ter aquele campo, de determinado tipo.
dicionárioaulas 05, 06
Estrutura de dados do Python que armazena pares de chave e valor, como {"nome": "Ana", "gostos": ["música"]}. Acessado pela chave: perfil["nome"]. No curso, dicionários são usados para guardar o perfil do usuário, a base de dados de produtos e o estado de cada usuário separado por user_id.
E
↑
endpointaula 07
Sinônimo de rota. Um endereço específico dentro de uma API que aceita requisições e devolve respostas. /chat é um endpoint. /status é outro. Cada um tem um método HTTP associado (GET para buscar, POST para enviar dados) e uma função Python que é executada quando uma requisição chega.
F
↑
FAQaula 09
Frequently Asked Questions, perguntas frequentes. No chatbot, um dicionário com palavras-chave mapeadas para respostas prontas. Quando o usuário pergunta o horário de funcionamento, o endereço ou a política de troca, a resposta já existe e é sempre a mesma. Responder pelo FAQ não consome tokens e é instantâneo.
FastAPIaula 07
Framework web para criar APIs com Python. Resolve toda a parte técnica de receber requisições HTTP, validar dados e devolver respostas. Com app = FastAPI() e decoradores @app.post(), qualquer função Python vira um endpoint disponível na rede. Também gera automaticamente a página /docs para testar a API no navegador.
fetch()aula 07
Função nativa do JavaScript que faz requisições HTTP a partir do navegador. Usada com async/await para enviar mensagens do front-end ao back-end e receber a resposta sem recarregar a página. JSON.stringify() converte o objeto JavaScript para texto JSON antes de enviar; .json() converte a resposta de volta para objeto.
framework webaula 07
Um conjunto de ferramentas e regras já prontas que agilizam o desenvolvimento de aplicações web. Em vez de escrever do zero tudo o que envolve receber e responder requisições HTTP, você usa uma base que já resolve essas partes. O FastAPI é um framework web para Python.
frequency_penaltyaula 06
Parâmetro da API da OpenAI que penaliza palavras que já apareceram na resposta, reduzindo repetições. Valores entre 0 e 2. Junto com o presence_penalty, ajuda o modelo a variar o vocabulário e não ficar repetindo as mesmas expressões numa mesma resposta.
front-endaula 07
A parte do sistema que o usuário vê e com que interage, rodando no navegador. No chatbot, é o arquivo HTML com o campo de texto, o botão de enviar e o histórico de mensagens. O front-end nunca deve conter a chave da API ou lógica de negócio crítica, porque o código-fonte HTML é acessível para qualquer pessoa.
G
↑
globalaulas 06, 07
Palavra-chave Python que permite a uma função modificar uma variável definida fora dela. Sem global perfil dentro da função, qualquer atribuição a perfil criaria uma variável local que desaparece ao término da função. Num servidor FastAPI, o global garante que o perfil e o histórico do usuário persistam entre requisições.
H
↑
histórico de mensagensaula 03
A lista de mensagens enviadas à API da OpenAI em cada chamada. Cada mensagem tem um role (system, user ou assistant) e um content. Incluir mensagens anteriores na lista é o que dá memória ao chatbot: a IA lê todo o histórico para gerar a próxima resposta. O histórico cresce com cada troca e precisa ser limitado para controlar o custo.
HTTPaula 07
HyperText Transfer Protocol. O protocolo padrão da web, um conjunto de regras que define como computadores trocam informações pela internet. Toda vez que você abre uma página no navegador ou o chatbot chama a API da OpenAI, a comunicação acontece via HTTP. Cada mensagem carrega um método (GET ou POST), um endereço e um corpo com os dados.
J
↑
JSONaulas 05, 07
JavaScript Object Notation. Formato de texto para estruturar dados em pares de chave e valor, como {"texto": "oi", "user_id": "abc123"}. É o formato padrão de troca de dados entre front-end e back-end, e entre o chatbot e a API da OpenAI. Em Python, json.loads() converte texto JSON em dicionário; em JavaScript, JSON.stringify() converte objeto em texto JSON.
L
↑
LLMaulas 03, 09
Large Language Model, modelo de linguagem de grande escala. É o tipo de IA por trás do ChatGPT e do GPT-4.1-mini. Treinado em enormes volumes de texto, consegue gerar respostas coerentes e contextualmente adequadas. Mas tem limitações: não tem acesso a dados externos por padrão, pode alucinar e não é determinístico, ou seja, a mesma pergunta pode receber respostas diferentes.
localStorageaula 08
Espaço de armazenamento dentro do navegador, separado por domínio. Diferente de uma variável JavaScript que desaparece ao fechar a aba, o que fica no localStorage persiste entre sessões. Usado para guardar o user_id do chatbot: na primeira visita gera e salva, nas seguintes lê e reutiliza.
loggingaula 10
Módulo nativo do Python para registrar eventos que acontecem no sistema enquanto ele roda. Diferente do print(), os logs têm data, hora e nível de gravidade: INFO para eventos normais, WARNING para situações que merecem atenção e ERROR para falhas. Podem ir para o terminal e para um arquivo em disco simultaneamente.
loop / while Trueaula 01
Estrutura de repetição que executa o mesmo bloco de código continuamente. O while True cria um loop infinito: o chatbot fica esperando a próxima mensagem do usuário para sempre, exatamente como a Alexa fica "ouvindo" o ambiente. O break é o que permite sair do loop quando necessário.
M
↑
max_tokensaula 04
Parâmetro da API da OpenAI que limita o tamanho máximo da resposta gerada. Um token corresponde aproximadamente a 0,75 palavras em inglês ou um pouco menos em português. Limitar os tokens reduz o custo e garante respostas curtas quando necessário. Para respostas de chatbot, valores entre 80 e 200 costumam ser adequados.
middlewareaula 07
Código posicionado entre o servidor e as funções de rota, que intercepta todas as requisições que chegam e todas as respostas que saem. Registrado uma vez com app.add_middleware(), age automaticamente em tudo. O CORSMiddleware adiciona os cabeçalhos necessários para o navegador aceitar requisições de outras origens.
modeloaula 03
O motor de inteligência artificial usado para gerar as respostas. No curso, usamos o gpt-4.1-mini, um modelo da OpenAI com bom equilíbrio entre qualidade e custo. É passado como parâmetro na chamada à API. Modelos diferentes têm capacidades, velocidades e custos diferentes.
N
↑
NFD / normalizar()aula 02
NFD é uma forma de decomposição de caracteres Unicode que separa a letra do acento, permitindo remover os acentos sem perder as letras. A função normalizar() aplica NFD e depois filtra os caracteres de acento, convertendo "café" em "cafe" e "não" em "nao". Usada em todas as comparações de texto para que "Sim", "sim" e "sím" sejam tratados como a mesma palavra.
O
↑
os.getenv()aulas 03, 07
Função Python que lê o valor de uma variável de ambiente do sistema operacional. Usada para carregar a chave da API da OpenAI sem escrevê-la diretamente no código. os.getenv("OPENAI_API_KEY") retorna o valor da variável se ela existir, ou None se não existir. Junto com o arquivo .env e o load_dotenv(), garante que credenciais nunca fiquem expostas no código.
P
↑
perfil do usuárioaula 06
Dicionário Python que guarda informações sobre o usuário coletadas durante a conversa, como nome e gostos. O perfil é mantido em variáveis globais no servidor e injetado dinamicamente no system prompt antes de cada chamada à IA. É o que permite ao chatbot personalizar as respostas sem precisar perguntar o nome a cada mensagem.
portaaula 07
Um número que identifica qual serviço está sendo acessado num endereço de rede, como um ramal dentro de um número de telefone. O uvicorn usa por padrão a porta 8000, então o endereço completo do servidor local fica http://127.0.0.1:8000. Se dois servidores rodarem ao mesmo tempo, precisam de portas diferentes.
promptaulas 03, 04
O texto enviado para o modelo de IA para orientar sua resposta. Composto por três partes: o system prompt (que define o comportamento geral), as mensagens do usuário e as respostas anteriores da IA. Um prompt bem estruturado com Contexto, Tarefa, Formato e Restrições produz respostas mais previsíveis e dentro do esperado.
Pydanticaula 07
Biblioteca Python para validação de dados. Já vem junto com o FastAPI. Você cria classes que herdam de BaseModel para definir o formato esperado dos dados. O Pydantic garante que, se os dados chegarem fora do formato declarado, o FastAPI devolve um erro antes de entrar na função.
R
↑
RAGaulas 08, 09
Retrieval Augmented Generation, geração aumentada por recuperação. Padrão em que você busca dados reais de uma fonte externa e os injeta no prompt antes de chamar a IA. A IA lê esses dados e os usa para responder, em vez de depender do que aprendeu no treinamento. Evita alucinação em perguntas sobre dados específicos como preços, estoque ou horários.
requestsaula 07
Biblioteca Python para fazer requisições HTTP. Com requests.post(url, json=dados) você envia uma requisição POST para qualquer API a partir de um script Python, sem precisar de um navegador. O parâmetro json= converte automaticamente o dicionário para JSON. Usada no exercício do cliente Python que conversa com o back-end FastAPI.
returnaula 01
Comando Python que encerra uma função e devolve um valor. Numa função de chatbot, return resposta devolve o texto que será exibido ao usuário. Num endpoint FastAPI, return {"resposta": texto} devolve um dicionário que o FastAPI converte automaticamente para JSON.
roleaula 03
O papel de cada mensagem no histórico enviado à API da OpenAI. São três: system define o comportamento geral do chatbot e fica sempre na primeira posição; user é o que o usuário enviou; assistant é o que a IA respondeu. O modelo usa o contexto de todas as mensagens para gerar a próxima resposta.
rotaaulas 07, 09
Um endereço dentro de uma API combinado com o método HTTP que ele aceita. @app.post("/chat") define a rota /chat para o método POST. @app.get("/status") define a rota /status para o método GET. Quando uma requisição chega nesse endereço com esse método, a função logo abaixo é executada.
S
↑
separação de responsabilidadesaula 10
Prática de organizar o código de forma que cada função faça uma coisa só. O critério é conseguir descrever o que a função faz sem usar "e". Uma função que classifica a mensagem e busca dados e chama a IA tem três responsabilidades. Separadas, cada parte é mais fácil de testar, modificar e entender.
status HTTPaula 07
Número que acompanha toda resposta de um servidor indicando o resultado da operação. 200 significa sucesso. 422 indica que os dados da requisição não bateram com o que o BaseModel esperava. 500 é erro interno do servidor, geralmente uma exceção no código não tratada. É o primeiro lugar para olhar quando algo não funciona.
system promptaulas 03, 04
A primeira mensagem do histórico, com role: "system", que define o comportamento geral do chatbot antes de qualquer troca com o usuário. Um bom system prompt tem quatro partes: Contexto (quem é o bot e onde está), Tarefa (o que deve fazer), Formato (como deve responder) e Restrições (o que não deve fazer ou dizer).
T
↑
temperaturaaula 04
Parâmetro da API da OpenAI que controla o quanto o modelo varia suas respostas. Vai de 0 a 2. Valores próximos de 0 produzem respostas mais previsíveis e fiéis ao contexto, ideal para respostas sobre dados reais. Valores maiores aumentam a criatividade e variação, adequados para conversas livres. No curso, usamos 0.1 para produto e 0.4 para conversa.
tokenaulas 03, 04
A unidade de cobrança da API da OpenAI. Corresponde aproximadamente a 0,75 palavras em inglês. Cada chamada à API consome tokens tanto da entrada (o que você enviou) quanto da saída (o que a IA respondeu). Históricos longos e prompts extensos aumentam o custo por chamada. O parâmetro max_tokens limita o tamanho da resposta para controlar o custo.
try / exceptaulas 04, 07
Estrutura Python para tratar erros sem travar o programa. O bloco try tenta executar o código; se ocorrer uma exceção, o bloco except é executado em vez de o programa parar. Em chatbots, o try/except envolve as chamadas à API da OpenAI: se a chave estiver errada, o servidor estiver fora do ar ou houver timeout, o chatbot devolve uma mensagem amigável em vez de um erro técnico.
U
↑
user_idaula 08
Identificador único gerado para cada usuário, que permite ao servidor separar perfis, históricos e memórias distintas. Gerado no front-end com crypto.randomUUID() e salvo no localStorage, é enviado junto com cada mensagem. No back-end, é a chave do dicionário usuarios que guarda o estado de cada pessoa.
uvicornaula 07
Servidor web leve para aplicações Python modernas. Fica rodando em segundo plano, escutando a porta definida e repassando cada requisição recebida para o FastAPI. É o "porteiro" do sistema: o FastAPI são as regras do negócio, o uvicorn é quem abre a porta. Iniciado com python -m uvicorn main:app --reload, onde --reload reinicia o servidor automaticamente ao salvar o arquivo.
V
↑
variávelaula 00
Um nome que aponta para um valor na memória do programa. nome = "Ana" cria uma variável chamada nome com o valor "Ana". O valor pode mudar durante a execução. Variáveis dentro de funções são locais e desaparecem quando a função termina; variáveis globais persistem enquanto o programa roda.
Vector Storeaula 08
Banco de dados especializado em armazenar e buscar conteúdo por similaridade semântica, e não por palavras exatas. Documentos são transformados em vetores numéricos (embeddings) que representam seu significado. Quando uma pergunta chega, o sistema busca os trechos mais relevantes sem precisar ler o documento inteiro, tornando a busca rápida e eficiente. O upload do arquivo é feito uma vez e as consultas seguintes são econômicas.
